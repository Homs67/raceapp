Overview

Dashboard system

While recording, the screen is a grid of widgets the driver arranges themselves — several dashboards, swiped between. Everything for it lives under raceApp/Dashboard/.

The model

TypeWhat it is
DashboardA name and an ordered list of placements. Order is reading order; it is not a set of coordinates.
WidgetPlacementid, kind, size, and a settings: [String: String] dictionary for per-widget options (e.g. which acceleration run to show).
WidgetKindThe library: every widget with its title, category, supported sizes, default size, and options. Two special kinds: .empty (a hole left by removing a widget) and .unknown (a kind a newer build saved, dropped on load).
WidgetSizeSmall = 1 cell · Medium = 2 cells side by side · Large = 2 × 2.
GridSpec2 rows × 4 columns in landscape; transposed to 4 × 2 in portrait. The same placement list lays out in both.

Storing order instead of positions is what makes portrait/landscape reflow, drag-to-reorder and "does this fit?" all the same function.

From bus to pixels

  • DashboardLiveFeed is the only place the dashboard reads the bus. It applies the fresh(…) rule, picks sources (e.g. no phone-axis G fallback while a RaceBox owns motion), and keeps accumulators such as peak G and the G trail, which reset when a new session starts. One deliberate exception to "stale means absent": while the CAN stream owns the adapter, pedal, brake, steering and RPM are held for up to 12 s (the adapter may be rotating its single filter), and LiveSnapshot.canStale flips after 2.5 s so the widgets dim the held value via .heldValue(_:) instead of blanking it. Link loss ends the stream and the normal 1–2 s rule returns.
  • LiveSnapshot is a plain Equatable value. LiveSnapshot.demo(track:) is a fixed, plausible snapshot used by the widget gallery, edit mode and Settings preview.
  • WidgetContext is what a widget receives: its placement, content size, orientation, the snapshot, units, edit state and track.
  • WidgetView is an exhaustive switch over WidgetKind — adding a kind without a view is a compile error.
  • Exception: CameraWidget reads AppModel directly, because camera preview layers aren't snapshot data.

Layout

Packing

GridPacker is pure and unit-tested:

  1. Pack — walk the placements in order and put each at the first free position, row by row (like iOS Home Screen). Anything that doesn't fit lands in overflow.
  2. Stretch (view mode only) — widgets in a partly filled row share its width. Three smalls in a row of four become thirds. Edit mode shows the strict grid so empty cells are real tap targets.
  3. fits checks both orientations. A layout's area being ≤ 8 cells does not mean it fits — every edit is validated in landscape and portrait.

Geometry

GridGeometry turns unit rectangles into points:

  • Edge to edge. The grid fills the screen. Only the sensor housing is kept clear: the top in portrait, and only the side with the Dynamic Island in landscape (iOS reports the same inset on both sides; the interface orientation says which one actually has the island).
  • Corners. A cell that meets the rounded glass in a corner gets 24 pt extra padding — on the whole cell in landscape (title and value stay on one vertical line), on the bottom only in portrait (side padding never changes).
  • Borders are drawn once by GridBordersCanvas at half-pixel offsets so shared edges stay 1 pt. In the live view, edges on the screen boundary aren't drawn and lines fade to black over their last 20 pt; preview and edit show full outlines.
  • Preview and edit lay the grid out for the bare screen and scale the whole thing to fit between 12 pt under the navigation bar and 24 pt above the bottom — nothing reflows.

Type and spacing rules

Rule · three sizes, no scaling

Defined in WidgetMetrics and nowhere else:

  • 21 pt — widget titles (Sofia Sans Condensed ExtraBold, uppercase, tracked), and the minimum for any text in a widget. Quieter text gets a lighter weight, never a smaller size.
  • 100 pt — hero values (lap time, delta, RPM, speed) at medium and large, when the widest possible string fits; otherwise 48 pt.
  • 48 pt — every other value.
  • At least 16 pt between a title and its content; 16 pt cell padding.

No minimumScaleFactor. A value that doesn't fit its cell is a layout bug, solved by not offering that size.

Gotcha · fonts

Sofia Sans Condensed's static files register under different family names per weight, so Font.sofia(_:_:) resolves explicit PostScript names (SofiaSansCondensed-Bold, …). Its digits are proportional by default — always use .sofiaNumeral / .monospacedDigit() for numbers, or values jitter as they change.

During a recording

  • Pages are a horizontal paging ScrollView, not a TabView: the UIKit page host behind TabView insets and recentres pages by the safe area, which no combination of modifiers fully undid.
  • The toolbar is hidden until the driver taps (with a light haptic): elapsed time, page pills, STOP. It slides in from the top in landscape and the bottom in portrait. STOP is the only way out — the dashboard can't be swiped away.
  • A pulsing red dot beside the Dynamic Island shows recording is live. It sits next to the island: the island is a system layer drawn above every app, so nothing inside it would be visible.

Edit mode

Long-press a widget when not recording, or Settings → Dashboards → Edit.

  • DashboardEditController holds a working copy and validates every mutation against both orientations.
  • One DragGesture(minimumDistance: 0) per widget with a 250 ms lift timer handles everything: a quick tap opens options, a still hold lifts, hold-then-move reorders with live reflow. (A long-press-then-drag gesture sequence swallowed plain taps.)
  • Removing leaves a hole (.empty) of the same size so nothing else moves. Holes show as dashed + targets and are trimmed from the end when editing finishes.
  • The widget gallery (WidgetSheets) renders every widget at its real cell size with demo data, grouped by size, up to four small tiles per row. A size that doesn't fit explains how many free cells it needs instead of being greyed out.

Persistence

DashboardStore keeps all dashboards in one dashboards.json beside the sessions folder. It seeds Lap Timer and Driving on first launch, carries a seedVersion so a new default can be offered to existing installs once, and never fails the whole file over a widget kind a newer build wrote.

Recipe: adding a widget

  1. Declare it in Dashboard/Model/WidgetKind.swift: add the case, then its title, category, supportedSizes, defaultSize, and its place in library (gallery order). Mark it isHero only if it's a single big number.
  2. Give it data. Add a field to LiveSnapshot, fill it in DashboardLiveFeed.tick (read through fresh(…); nil means "no data"), and give it a realistic value in LiveSnapshot.demo so the gallery isn't blank.
  3. Draw it in the matching file under Dashboard/Widgets/. Use WidgetValue, WidgetSecondaryValue and WidgetCaption rather than your own fonts; switch on context.size for layout only.
  4. Dispatch it in WidgetView in WidgetChrome.swift — the compiler will point you there.
  5. Options (optional). Return a WidgetSetting from WidgetKind.settings; read it from context.placement.settings. The options sheet renders it automatically and no data migration is needed.
  6. Check it in the gallery at every size in both orientations, with the demo snapshot and with nil data.
