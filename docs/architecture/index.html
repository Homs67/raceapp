What the app is

raceApp (product name Live Data) is an iOS app that records driving sessions — at the track or on the road — and shows a live, customisable dashboard while it does. It was built around one car, a 2022 Mazda MX-5 (ND2), and three kinds of hardware:

  • The iPhone itself — GPS, a 100 Hz motion sensor, a barometer.
  • An OBD-II Bluetooth adapter (ELM327 protocol, e.g. Veepeak OBDCheck BLE+) plugged under the dash — engine data by polling, or raw CAN-bus signals such as steering angle and brake pedal.
  • A RaceBox (Micro, Mini or Mini S) — a 25 Hz GNSS receiver with its own accelerometer and gyro, far more precise than the phone.

After a session you get laps, a delta to your best lap, graphs, video synced to the data, and a CSV export. A post-session coaching engine is the long-term product goal (see 01-architecture.md, 02-coaching-engine.md) — it is not built yet. Everything on this site describes code that exists today.

The 60-second mental model

Every piece of data in the app is the same shape: a channel name, a number and a timestamp — (gps.speed, 31.4, 1842.07). Sources publish those samples onto one in-memory hub, the TelemetryBus. Everything else reads from it.

Three consequences of this shape explain most of the code:

  1. Sources don't know who's listening. The OBD driver has no idea a dashboard or a recorder exists — it publishes obd.rpm and moves on. Adding a source never touches the UI.
  2. The live view and the recording are different reads. The dashboard reads the bus's latest value ten times a second and can afford to skip samples. The recorder taps every sample at full rate and writes it to disk.
  3. A session is just files. No database: a folder per session with a JSON manifest and one append-only binary file per channel. Anything that analyses a session — graphs, laps, export, video sync — reads those files back.

Suggested day-one reading

  1. This page, then Data sources and Telemetry pipeline. Together they cover the core idea.
  2. Open raceApp/Model/AppModel.swift. It is short and wires every component together — it's the best single file for seeing the shape of the app.
  3. Read raceApp/Model/TelemetryBus.swift (90 lines) and Packages/SessionKit/Sources/SessionKit/SessionRecorder.swift.
  4. Run the app in the Simulator in demo mode — no car or hardware needed. See Dev workflow → Demo mode.
  5. Run swift test inside Packages/SessionKit. The tests are the most precise description of the maths.
