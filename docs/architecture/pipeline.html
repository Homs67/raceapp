Overview

Telemetry pipeline

What happens to a sample between a sensor producing it and it being on disk — and how a session is read back for review and export.

The sample

Everything is a scalar sample: (ChannelId, Double, TimeInterval).

  • ChannelId is a namespaced string — gps.speed, obd.rpm, rb.yawRate — defined in Packages/SessionKit/…/ChannelId.swift. One channel, one physical quantity, one unit.
  • The timestamp is monotonic uptime in seconds (monotonicNow()), not wall-clock time. It can't jump when the phone's clock syncs. Wall-clock time enters a session in exactly two places: the manifest's startedAtUTC, and the *.wallTime channels the GNSS sources write for clock audits.

TelemetryBus

raceApp/Model/TelemetryBus.swift — about 90 lines, and the most important 90 lines in the app. It's lock-based rather than an actor because sources call it from Bluetooth and sensor queues at up to 100 Hz.

Rule · "never a fake zero"

Requirement R2.5. A value that has stopped updating is absent, not frozen and not zero. Always read through fresh(…, maxAge:) and render nil as —. A gauge that holds its last value after the adapter disconnects is a bug.

Recording a session

One button. AppModel.startRecording() resets per-session state (sensor recalibration, the RaceBox frame, lap metrics) and asks RecordingCoordinator to start. From then on:

  1. Start. SessionRecorder.start creates the session folder and writes manifest.json with status recording before any data — a crash one second in still leaves a recoverable session. It then attaches the bus tap.
  2. Every sample is appended to its channel file, folded into running highlights (distance, max speed, peak G, max RPM, elevation gain), checked for OBD dropouts, and fed to the auto-stop rule.
  3. Flushing. SessionWriter buffers each channel and writes when the buffer passes 4 KB, plus an explicit flush every second. A crash loses at most the unflushed tail (R1.5).
  4. Stop. The tap is detached, the stream drained, files closed, and the manifest finalised: status complete, highlights, gaps, per-channel sample counts, end time. Camera clips are attached in a beforeStop hook.

Auto-stop

AutoStopMonitor (R1.6) stops a forgotten recording when the OBD link has been gone and the car has been stationary for 5 minutes. It deliberately ignores the RaceBox for "engine on" — a logger on a permanent 12 V feed keeps reporting long after the ignition is off.

On disk

SessionStore is a directory per session; there is no database. The manifests are the index, which makes crash recovery trivial.

<Application Support>/LiveData/
├── dashboards.json              ← dashboard layouts (DashboardStore)
└── sessions/
    └── <uuid>/
        ├── manifest.json        ← metadata, highlights, gaps, channel stats
        ├── channels/
        │   ├── gps.lat.f64      ← 16 bytes per sample:
        │   ├── gps.speed.f64       Float64 LE time + Float64 LE value
        │   ├── car.latG.f64
        │   └── …
        └── videos/              ← optional camera clips

The channel format is deliberately dumb: fixed 16-byte records, append-only, readable with three lines of Python. ChannelReader reads them back; nothing ever rewrites a channel file.

Export

SessionExporter writes three files for the share sheet:

  • CSV on a fixed timeline — 10 Hz normally, rising to 25 Hz when position arrives that fast so a RaceBox isn't downsampled. Each cell holds the last value at or before its instant, but only while that value is fresh for its channel (e.g. 0.2 s for rb.*, 2.5 s for gps.*), so a sensor blackout shows as blank cells instead of a frozen number. Opens in Excel; imports into RaceChrono.
  • JSON sidecar — the manifest enriched with measured rates per channel (ChannelStats), OBD timing, and the post-session G-force check (GForceValidator).
  • Raw JSON — every sample at its native rate, unresampled, for accuracy audits.

Importing RaceBox memory

A Mini S or Micro can record on its own. Its memory is one continuous log, not files, so raceApp/Model/RaceBoxMemoryImporter.swift reconstructs drives during download:

  • A start/stop marker saved by the device closes the current drive.
  • A gap of more than two minutes between records' own GPS timestamps also closes it — a logger unplugged mid-drive leaves no marker.
  • Each drive is written through an ordinary SessionRecorder on its own timeline starting at zero, so an imported drive is indistinguishable from a live one. Fragments under 25 records are discarded.
Gotcha

Subscribe to RaceBoxSession.historyEvents before calling startDownload(). The device starts streaming the instant it answers; subscribing afterwards silently drops the first records of every drive. This bug existed and was caught only because a synthetic 600-record dump imported 598.
